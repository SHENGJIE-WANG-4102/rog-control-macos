# ROG Control for macOS

简体中文 · [English](README.md) · **v0.3** · [更新日志](CHANGELOG.zh-CN.md)

面向 **ASUS ROG 枪神 9 系列**的原生 macOS 控制中心：原厂性能档位、风扇监控，以及 CPU／GPU 传感器视图。

**支持 ROG 枪神 9 系列，但目前仅在 G815LW 上做过实机测试。** 其他型号与 BIOS 版本尚未验证，可能需要补充已审查的固件配置后才能使用模式控制。

**当前为实验性早期版本。** 原厂档位控制已在 macOS 26 下的 ROG Strix G18 **G815LW（枪神 9）** 上实机验证。固件桥接驱动只接受一份已审查的 DSDT 指纹，并不是通用 ROG 驱动。本项目由社区独立开发，并非 ASUS 官方产品。

## 功能状态

| 功能 | 当前状态 |
| --- | --- |
| 安静／性能／Turbo 三档 | 已实测，确认固件档位读回和风扇转速变化 |
| CPU、GPU、第三风扇转速 | 已实测；应用可见时支持每秒刷新 |
| CPU 温度 | 读取已有 SMC 温度传感器 |
| CPU 封装功耗 | 读取封装能耗对应的 SMC 项，不混用核心域功耗 |
| CPU 频率 | 尝试读取 `powermetrics` 的采样平均频率；系统不提供时显示不可用 |
| GPU 频率、功耗、温度 | 已通过 NVIDIA RM 共享遥测实测；测试组合为 RTX 5080 Laptop、NullMoth NVRM 2.4.3 / NVIDIA 610.57.04 |
| 显存分配、显存温度／时钟、GPU 利用率 | 同一 RM 后端已实测；界面每秒刷新 |
| 授权 | 安装控制组件时授权一次，后续打开软件自动连接 |
| CPU 自定义功耗上限／风扇曲线 | 要求桥接驱动 1.5.0，校验安静预设下限；此前 1.4.0 已在 G815LW 测试风扇响应、最高 175／175W 目标读回及原厂恢复。新版安静预设实机验证与持续功耗约束验证仍待完成 |
| 亮度、键盘灯 | 尚未实现 |

缺失的传感器数据会明确显示为“不可用”，不会填入估算的额定值。CPU 功耗是传感器导出的封装功耗估计，不代表整机插座功耗；平均频率也不代表最快核心的瞬时峰值。

原厂档位可影响固件的控制策略，但这不等于已经验证了自定义 PL1／PL2 或 GPU TGP 调节。

### 自定义调校（v0.3）

应用在同一窗口内提供“监控”和“调校”两个标签页，切换保留草稿，监控持续每秒刷新。“调校”页可编辑 CPU、GPU、第三风扇的八点曲线及 CPU PL1／PL2。应用设置需要桥接驱动 **1.5.0**、接通电源、固件指纹匹配，并先明确读取原厂曲线。功耗限制为 **5 ≤ PL1 ≤ PL2 ≤ 175W**，界面、管理员组件和内核均校验。温度范围为 20–100°C，须严格递增；风速范围为 0–100%，不能随温度下降，且整条曲线不得低于安静预设的对应温度插值。末点不锁定 100%。原厂曲线按原样显示，不会静默修改；不符合自定义规则的表格需编辑后才能应用。

可直接拖动曲线上的点，与表格双向同步。横轴为 20–100°C，纵轴为 0–100%，网格每 10 一格，拖动按 1°C／1% 取整。温度至少与邻点相隔 1°C。提高风速超过后续点时自动抬高受影响点；降低风速低于前序点时自动降低受影响点。下限来自明确读取的安静模式曲线，在对应温度线性插值；灰色虚线表示该下限。末点也可以调低，受相同下限约束，不强制 100%。校验同时覆盖点之间及首末点外延；若直线段或末点延伸会低于安静预设，编辑器自动抬高必要的点。内核使用相同插值规则拒绝低于下限的请求。

拖动保持抓取偏移；点击空白或只点击点不改变数据。拖出图表仍约束到有效边界，禁用编辑时立即停止拖动。表格完成编辑后执行相同联动与下限约束。拖动及键盘编辑都只改变草稿，三个风扇及功耗目标通过检查后才可明确应用。

“保存方案…”将编辑中的三个曲线和 PL1／PL2 保存为 JSON；先读取原厂曲线后，可用“载入方案…”回填编辑器，再明确点击应用。方案格式包含版本与 G815LW 机型标识，拒绝未知格式、其他机型、额外字段或越界数值。保存、载入及预览不发送硬件请求，也不会在登录时自动应用。窗口较小时可滚动查看全部控件；每秒刷新保留当前草稿和输入焦点。

此固件写入曲线后会进入手动模式（`FANM=4`），CPU 功耗端点只有在该模式下才接受设置。三个风扇曲线和两个功耗目标作为一次明确操作发送；部分写入失败时尝试恢复原厂档位，并记录是否读回确认。**同步固件调用若卡住，恢复逻辑无法中断它。** 开机、关闭应用和自动传感器刷新都不读取原厂曲线或写入调校设置；登录后也不会自动重应用。

功耗确认读取固件目标字节 `M6F0`／`M6F1`，不等于已经验证负载下的持续功耗。曲线目前只确认固件应答及手动模式，不能读回当前自定义曲线；原厂曲线查询返回的是预设表。G815LW 已实测三个原厂曲线读取、自定义风扇响应、80／100W 及 175／175W 目标读回，并恢复 Turbo。三风扇曲线设为 100% 时，一轮约 12 秒、24 线程 CPU 测试的封装温度读数最高为 75°C，风扇读数约为 6600／6300／7500 RPM。这是短时功能测试，不代表长期稳定性验证。

这轮高频 SMC 封装功耗采样出现零值与尖峰交替，不能仅凭原始读数确认真实瞬时功耗或持续硬件上限。PL1／PL2 目标也不是瞬时封装功耗的绝对硬上限：[Intel 功耗控制说明](https://edc.intel.com/content/www/us/en/design/products/platforms/details/arrow-lake-s/core-ultra-200s-series-processors-datasheet-volume-1-of-2/005/package-power-control/)将 PL1 定义为平均功耗阈值，PL2 则是在越限后触发快速限制的阈值。本实现不读取或修改可选的 PL3／PL4。长期稳定性、封装功耗独立核验、其他机型／固件和 GPU TGP 调节仍待验证。

桥接驱动 1.5.0 仅在明确读取操作中额外查询安静曲线，无需切换原厂模式；开机与传感器刷新不执行该查询。1.4.0 的既有实测不代表新的安静下限逻辑已经过实机验证。

点击“恢复原厂策略”可回到读取曲线时的原厂档位；在主窗口选择原厂档位也可退出手动模式。如果重启后固件仍保留手动模式、软件尚无原厂基线，先在主窗口选择原厂档位，再明确读取曲线。桥接驱动更新需要重启；仅构建项目不会安装驱动或改变启动配置。

### NVIDIA 遥测（v0.2）

读取器创建自己的 RM 客户端，以只读方式映射 `RM_USER_SHARED_DATA`，每次快照后释放对象和映射。不初始化或重置 GPU，不访问原始寄存器，不设置频率／功耗上限，也不修改已安装的图形驱动。RM 读取本身无需管理员权限；控制组件仍需授权来切换固件档位、采样 CPU。

RUSD 没有布局版本协商，因此目前仅接受已核对的 NVRM **2.4.3** 组合；其他版本需先核对 ABI。无效、不一致、越界或过期的字段分别显示为不可用。轮询字段须观察到 RM 时间戳实际推进，使用本机单调时钟计时，连续三秒不更新即失效，不直接与系统墙上时间比较。启动或长时间闲置后最多等待半秒确认更新；PMA 显存分配数据使用 NVIDIA 的序列计数器校验。

GPU 主功耗读数为**瞬时 GPU 功耗**，不是设置的 TGP 上限。诊断 JSON 还包含平均 GPU 功耗、显存控制器忙碌率和 P-State。**显存分配／总量**指扣除保留区域后的 RM PMA 可分配池，不等于硬件标称容量；显存控制器忙碌率也不等于显存分配比例。显存时钟为驱动报告的实际时钟，不是 GDDR 有效传输速率。

无需管理员权限或固件请求即可读取传感器：

```sh
"dist/ROG Control for macOS.app/Contents/MacOS/ROGControl" --read-sensors
```

## 构建和运行

需要 Intel macOS 环境及 Xcode Command Line Tools。应用使用系统的 AppKit、Foundation、IOKit 和 Security 框架，无需额外包管理器依赖。

```sh
xcode-select --install
./script/build_and_run.sh
```

构建结果位于 `dist/ROG Control for macOS.app`。只编译、不打开窗口：

```sh
./script/build_and_run.sh --build-only
```

还支持 `--verify`、`--debug`、`--logs`、`--telemetry`。

原厂档位与监控兼容已加载的 `ROGFirmwareProbe` **1.3.0／1.4.0／1.5.0**，自定义调校要求 **1.5.0**。构建或打开应用不会安装内核扩展、重建系统缓存、修改 EFI 或启动参数。

### 固件桥接驱动

`Driver/` 包含桥接驱动源码与元数据，需要单独获取 [MacKernelSDK](https://github.com/acidanthera/MacKernelSDK)：

```sh
git clone https://github.com/acidanthera/MacKernelSDK.git Vendor/MacKernelSDK
./Driver/build.sh
```

也可通过环境变量 `MAC_KERNEL_SDK` 指定已有 SDK。脚本只生成本地 kext，不自动安装：内核扩展的部署与恢复取决于具体引导环境。不要直接删除固件指纹校验来尝试未经审查的机型。

已审查的机型与固件信息集中在 `Driver/Profiles.hpp`。系列名称不等于兼容性校验；新增条目前需要审查对应机器的固件并验证接口行为。

保留 `ROGFirmwareProbe` 名称是为了兼容已经实测的驱动接口。

## 使用方法

1. 确认匹配的桥接驱动已加载，打开应用。
2. 点击“授权一次…”，在 macOS 原生对话框中完成管理员授权，安装控制组件。
3. 选择安静、性能或 Turbo，点击“应用档位”。仅接通电源时允许切换，切换后读回固件状态确认。
4. 按需启用或关闭自动读取。关闭应用会停止界面轮询，所选原厂档位保留。

后台组件随系统启动后只等待请求，不会在空闲启动路径读取固件、采样传感器或自动切档。它只接受指定用户运行的、代码签名身份经过批准的 GUI 请求。签名检查、本地套接字权限、固件指纹和档位范围校验分别限制调用范围。重新编译后应用代码身份改变，更新控制组件时可能需要再次授权。

本地开发构建采用临时签名，未进行公证。当前界面为中文，项目提供中英文说明。

### 卸载控制组件

```sh
sudo /Library/PrivilegedHelperTools/com.macdriver.ROGControlHelper --uninstall
```

这会移除用户态控制服务，不移除单独安装的桥接驱动，也不改变当前原厂档位。应用本身可另行移除。

## 验证

```sh
./script/test.sh
```

这些测试检查请求边界，在主机模拟环境中运行实际固件命令函数，并使用模拟 RM 传输验证版本拒绝、字段失效、单位转换及失败后的资源释放；不代表固件一定响应或其他机型兼容。实机已经验证安静、性能两档切换、三个风扇转速读数、恢复到测试前的 Turbo 档，以及测试 GPU／驱动组合的实时 RM 遥测。

固件调用是同步执行的，用户态超时不能取消卡住的 ACPI／SMI 调用。驱动在 `start`、`stop`、`free` 中均不调用固件；写入只通过明确请求触发，并限制在原厂档位、三风扇曲线和 PL1／PL2 的固定端点，不开放任意 ACPI、EC、MSR 访问。曲线响应和功耗目标读回已做短时实测；持续硬件功耗约束与长期稳定性仍待进一步验证。

## 目录

- `Sources/`：原生应用、管理员组件、传感器读取与桥接客户端。
- `Driver/`：限定机型的固件桥接驱动。
- `Tools/`：桥接命令行客户端。
- `Tests/`：无需真实固件调用的命令边界与错误处理测试。
- `script/`：统一构建、运行、测试入口。

项目不包含个人诊断日志、系统备份、显卡驱动、固件表转储或 EFI 配置。
